# Contributing to URDF Studio

Issues and pull requests are welcome. No prior written invitation, separately
signed contributor agreement, copyright assignment or CLA form is required.
Read [LICENSE](LICENSE), especially section 5, before submitting code or documentation.

Submit only material you have the right to license on these terms; identify
third-party code and preserve its notices. Ordinary bug reports and discussions
do not assign your unrelated work or ideas.

## Send a change

1. Fork this repository and branch from the current `urdf-studio-main`.
2. Make a focused change, preserving attribution and identifying upstream code.
3. Add a meaningful regression check and report the checks run, their platform,
   and any failures already present on the unchanged base.
4. Open a PR targeting `amtellezfernandez/urdf-studio:urdf-studio-main`.
   Direct push access is not necessary.

For conversion defects, include a small robot/scene fixture, expected geometry
or joint semantics and a check independent of merely launching a simulator.
Keep distinct defects in separate PRs and do not duplicate changes already merged.
See README for the existing local developer checks; hosted Actions are not a
prerequisite for submitting a PR.

## Research modifications and project identity

Local noncommercial research modifications and same-team sharing are permitted.
Modifications put into use must be submitted upstream within 30 days of first
use or before publishing dependent results, whichever occurs first.
Unused exploratory edits and independently written research code/data are
outside that requirement. The maintainer decides which contributions to merge.

Contribution-only forks and PRs are permitted. Independent releases,
redistribution outside your research team, services and rebranded derivatives
require prior written permission even for academic/nonprofit projects. Accurate
citation and description of research changes remain permitted.
Commercial use requires a separate license. See LICENSE for the full scope,
including statutory/platform rights and third-party exceptions.
